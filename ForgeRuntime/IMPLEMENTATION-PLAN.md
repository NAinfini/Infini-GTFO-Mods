上位依据：[唯一总案](../../Infini-GTFO-Model-Site/Docs/rework/FORGE-COMPLETE-PLAN.md) 第 2、4.3、5、7、8、13、14 节。发生语义差异先核对总案与实际代码，不在本文件私自改写 canonical 合同。每个批次的"退出验收"是未来的门槛，不是测试通过记录。

本包对应两个工作单元：**U-RUNTIME**（阶段 F3，执行层）与 **U-NET**（阶段 F3N，网络层与社区修复）。U-NET 的前置是 U-RUNTIME。

## 允许推翻现有实现

总案第 5.2 与第 7 节明确允许重做统一节点合同、IR、编译器与 Runtime 执行层，目标是编辑期表达力与游戏内运行性能同时最优。现有 `Framework/` 是可用起点而不是必须保留的结论；不为保留现有代码而妥协结构。

这条对本包的具体含义：**编辑器编辑的图不是游戏里跑的东西。** 编译产物是一份扁平、预解析的执行计划，不是图的序列化。运行期不做字符串查表、不按 id 查字典、不在 tick 内分配。可变端口在编译期按实际计数展开成固定端口；pure 子图常量折叠；节点 id、能力 id、绑定 id 全部解析成密集整数索引；类型与单位在编译期核对完毕，运行期不重复检查；子图内联或降为显式调用，不保留解释层。

## 必须稳定的公开接口边界

| 合同 | 当前可用 | 后续补全要求 |
| --- | --- | --- |
| 模块 | `RegisterModule`、句柄 Publish/CancelScope/Dispose、`ObserveLifecycle` | 版本冲突原子失败，卸载取消拥有的工作 |
| 对象 | `EntityReference(Id, WorldEpoch, LifeEpoch)`、模块 resolver 与 observer、有界 `InspectEntities` | 查询分页与完成性；不能返回裸指针 |
| 事件 | `RuntimeEvent` 与 root/cause/scope/tick | 提交前后事件分开、必要的 source/owner/instigator 身份、稳定排序与跨域传播 |
| 命令结果 | 六类 status + none/confirmed/unknown commitState | 请求量、实际量、成本、部分成功；不把 handler 抛错自动当成未提交 |
| 时间/状态 | 有限 schedule、数值 contribution lease | 统一状态叠加、刷新与驱散、积分余数、声明的恢复；不新增专用 HoT 定时器 |
| 图与事务 | 受限 v1 Plan；可变端口元数据可解析但执行明确拒绝 | 以真实 IR 明确 lowering、输入与结果引用、预留与提交与释放 |
| 网络与恢复 | **无**。当前只明确拒绝迁移与检查点 | 见下面 F3N 全部批次 |

表中"后续"不是新增 C# 接口清单。先证明多个真实模块需要共同接口再定类型，不在骨架中放空服务、`NotImplementedException` 或万能 ServiceLocator。

## F3 — 执行层

### R3 — 共享对象、目标与事件合同收口

已落地的是实体观察登记、注销清理、只读保护，以及显式引用的有界检查：返回快照不可变、引用精确、显式标注 complete/partial/rejected；空的完整请求不与"观察不可用"混淆；actor 永远不在 self/source/owner/instigator/event-target 之间回退；关系是有向的，种类与伤害治疗极性都不隐含阵营。

仍未收口的部分：世界枚举与分页查询；提交前 request、提交后 fact 与 typed result 的完整区分；事件因果深度与原始作者 node/resource 回指；不允许重发的边界；跨语言正反例的最终冻结。

退出验收：敌伤、友伤、敌疗、友疗四组合，未知关系、无 actor、不支持 receiver、陈旧世界或生命、空集合，各有确定且互不相同的结果。

### R4 — 统一图执行与控制调度

已落地的是可变端口元数据的校验与精确 revision 解析：不剥字段、不改所有者与版本，从唯一注册定义中按精确能力 revision 和有界计数解析端口。**解析出的端口布局只是元数据**——没有 handler、权限、调度器或可执行 binding；v1 计划加载器像网站编译器一样明确拒绝可变端口的执行。

仍未做的是完整 lowering。把实际网站输出降为一种受验证的执行计划，支持所需的数据端口与结果引用、条件、分支和控制节点；迁移完成后移除被替代的 Plan 路径，不永久保留两套 VM。注册和加载阶段验证 graph cycle、类型与单位与 domain、节点修订、精确 binding 与权限闭包，执行时只做当前状态与成本复核。统一 Delay/Interval/Sequence/Parallel/Join/ForEach/Cancel 的拥有者、排序、完成和取消语义——并行表示受控逻辑并发，不准用线程池调用 GTFO。每 tick 预算被重复 Advance 共享，递归、队列、结果事实和实体查询各有可追踪的拒绝或延后，不能通过分域或换 scope 重置全局上限。

**Selector 查询是最贵的一环**，必须走工作预算；`all-target` 覆盖不足时明确报告，不静默截断。

退出验收：跨域数据依赖、循环与重入与错误类型拒绝、重复 tick、预算耗尽、公平排序与取消传播；编译往返无静默丢字段。另需给出冷/热加载、每 tick 预算、分配次数、GC 压力的实测前后对比，同设备同场景——没有实测数据不得声称性能达标。

同时要退休导入的 `Infini.ForgeRuntime` 原型源码。它当前被生产工程明确排除，只有 `ForgeRuntime.Tests` 引用它；它不是生产 API 也不是 fallback，退休是本批的显式收尾项。

### R5 — 结果、成本与事务基础

以 commandId 与事务身份记录 validate → reserve → commit → release。定义资源所有者、预留有效期、竞争仲裁和重复请求结果；动作和成本不能分别猜测成功。保留 succeeded/partial/rejected/failed/cancelled/expired 与 commitState；领域进入原生提交后失去读回证据要返回 unknown，不能标 none 后自动重试。处理多目标部分成功、逐目标实际量和部分扣费，不承诺外部不可逆副作用回滚——补偿必须是显式动作并保留原始提交证据。提交后的 facts 与真实成功对象关联；反射、吸血、分摊继承因果，并限制链长和每根事件预算。

退出验收：并发抢最后一份资源、重复消费、提交前后异常、释放与过期、部分成功与 unknown 提交，均不免费执行也不重复扣费。

### R6 — 周期效果与统一状态

在现有 scheduler 与 lease 上实现明确的首跳、有限终点、bound/detached、每跳重选或绑定集合、来源生命周期；不把错过的历史范围 tick 投给当前成员。分别定义固定每跳、连续速率、有限总量和原生被动回复的单位、精度与余数；共享调度但不混淆累计量守恒与 SkipMissed 策略。复用贡献层重算处理全部 25 种参数化状态：叠层、刷新持续时间、重置节拍、延长、免疫、驱散、解除本来源——到期不能用除法恢复旧属性。每跳检查目标与来源 epoch、关系与 receiver、权限与成本，记录请求量、有效量、溢出、抵抗、消耗与跳过数；无成功收据不推导有效量。

句柄类型（`timer`、`reservation`）必须有明确所有者。取消、到期、卸载、死亡、换装与世界切换清除本来源持有的任务与 lease；已提交的副作用不通过反向猜测回滚，不支持恢复时明确拒绝，不借新 epoch 静默重放。

退出验收：无抵抗的延后 1 秒 +5 HP 共 10 跳请求 50；立即首跳、终点、重复 tick、稀疏 tick、两来源、零乘数、死亡与换装、每跳欠费、整数余数分别验证。

## F3N — 网络层与社区修复（U-NET）

GTFO 原生的联网 API 质量很差，这是既有事实。第三方模组各自为战地打补丁，结果是玩家为了修几个 bug 要装一堆模组，而这些补丁之间互不知情、互相覆盖。总案第 4.3 节把这一层的责任划给 Forge Runtime：它不只是框架宿主，还是这套内容在多人环境下能正确跑起来的责任方。

本单元的前置是 R3–R6 的提交身份与可序列化状态稳定。N0 不依赖任何前置，可以立即开工。

### N0 — 修复类与网络类模组来源盘点

**这是本单元的第一项，当前完全没有做过。** 总案第 5.1 节那 20 个功能基础包是玩法来源；修复类与网络类模组是另一类来源，从未盘点。

盘点要回答三个问题：哪些修复值得收进 Runtime、哪些已经被官方补丁覆盖因而不必收、哪些与我们的架构直接冲突。每条候选记录它修的是哪个 GTFO 原生缺陷、来源包与版本、许可、复现条件、当前是否仍然复现。

盘点结果**单独成表**，不混进总案第 33 节的 125 组机制——修复不是玩法能力，两者的验收口径不同。

退出验收：盘点表覆盖当前 Thunderstore 上活跃的修复类与网络类包，每条有明确的收/不收结论与理由；不收的理由必须具体（已被官方补丁覆盖、与架构冲突、无法独立复现、许可不明），不能只写"暂不考虑"。

### N1 — 可靠性与去重

同一副作用只由权威端提交一次。重复网络包、乱序到达、迟到的旧 epoch 消息全部显式拒绝，不靠"多发几次总有一次到"。去重键、提交账本与拒绝原因必须可追踪；账本耗尽明确拒绝新消息，不驱逐已记录身份。

退出验收：重复包、乱序包、旧 epoch 包、账本满，四种情况各有确定结果且不产生第二次副作用。

### N2 — 权威端判定

source / owner / instigator / recipient 四个角色在网络语义下各自的提交权与可见性明确。客户端只发送已核验的请求或接收事实，不把本地表现当成已提交结果；表现事件不能回写游戏状态。权威变化（主机权威丢失、客户端提升）要在下一 tick 之前被正确观察到，不使用陈旧的权威基线。

退出验收：四个角色各自的请求在主机端与客户端分别得到正确的接受或拒绝；权威切换期间没有双重提交也没有静默丢弃。

### N3 — 迟加入与恢复

迟加入玩家的状态同步、检查点恢复后的世界一致性、主机迁移，作为一等场景设计，不是事后补丁。快照要包含剩余任务、最后提交序号、lease 与预留、计划版本、精度余数与必要的重解析映射；旧实体 ID 不直接复用到新 life。未验证的模式先保留拒绝，逐模式取得真实游戏证据后再开放；禁止通过 `BeginWorld`、重入 Generating 或重复首跳绕过限制。

退出验收：迟加入、断线重连、检查点恢复不重扣不重放首跳、主机迁移四类场景各自通过；不支持的模式明确中止而不是静默降级。

### N4 — 带宽与消息预算

同 tick 同类消息合批，状态同步走增量而不是全量重发，预算不足时明确降级并报告，不静默丢包。

**网络优化不得以牺牲 N1 的去重与 N2 的权威判定为代价**——少发一条消息导致一次副作用漏提交，是回归不是优化。

退出验收：给出消息条数、字节量、每秒同步频率、迟加入完整同步耗时、主机迁移恢复耗时的同场景前后对比。性能验收与功能验收分开记账。

### N5 — 能力握手

多人局内各端安装的模块与版本不一致时，在开局前握手确认。握手比较 API 与能力与 binding 与资源修订，以及实际权限闭包；不一致就明确拒绝或降级，缺模块的参与者在执行前收到精确原因。**不能在运行中才发现对端不认识某个节点。**

公开 SDK 不是不可信 native 代码的沙箱，握手也不要把它描述成沙箱。

退出验收：版本一致、模块缺失、binding 修订不符、权限闭包不符四种情况各有明确且可读的结果。

### N6 — 社区修复纳入

别人已经定位并修好的 GTFO 原生缺陷收进 Runtime，玩家装 Forge 就一起修了，不必再装五个补丁模组。纪律是硬约束：

**吸收的是问题与行为规格，不是实现字节。** 不复制许可不明的代码、DLL 或资产。有证据的行为规格独立实现；确需复用实际源码的，登记许可、版本与 notice。

每条修复登记它修的是哪个原生缺陷、来源包与版本、复现条件、验证方式。**修复清单与机制目录分开维护**——修复不是玩法能力。

与被替代模组的关系按总案第 4.1 节同一口径：原生修复验收通过后，对应的外部补丁不再是运行依赖；验收前如实声明仍在依赖。

退出验收：修复清单里每一条都有来源、复现条件、独立实现的证据和验证结果；没有任何一条只写"参考了某某包"而拿不出行为规格。

## F10 — 离线包与发布收口

从实际注册导出 manifest 与网站联调；只列已实现的绑定与精确版本、权限、验证级别。内容包不反向进入 Runtime 发行包，游戏不在线索取作者图。统一验证路径、大小、资源来源与 hash 与依赖闭包，拒绝超界、未知修订和自授权限；Development 默认不进入普通玩家依赖。按已核定的包身份生成可重复的产物清单与 hash，核对 SDK 单一版本。只有在新路径真实替代之后才清理旧注册、旧图执行、配置和外部执行依赖，同时保留用户内容、源包和权利证据。

安装到测试 profile 与发布需要当时的明确任务授权。

退出验收：从网站离线导出到独立测试 profile 的完整闭环；源码、二进制、包依赖和报告版本一致，不能只凭构建关闭任务。

## 尚未收口的具体项

`ForgeRuntime/tests/test_import_log.py` 的跨端 reader 用例仍硬编码 `site/map-balance-report.js`，而网站实际文件已改名为 `.ts`。这项修复归 Development 与网站责任任务，不引入 stub、跳过或复制替身。

`ForgeRuntime/PERFORMANCE-REVIEW.md` 的内容实际是 InfiniTweaks 的标记与 HUD 性能对照，不是 Runtime 的内容。它现在放在本目录只是历史遗留，是否移到 `InfiniTweaks/` 待用户决定。

## 聚焦验收矩阵

| 场景 | 必须检出的错误 |
| --- | --- |
| 模块注册失败 | 不留下半注册的 capability/handler/receiver，不覆盖同名 canonical |
| 同 ID 新生命 | 旧事件、lease、事务和排队动作均不能作用于重生对象 |
| 同 tick 两次 Advance | 不重置预算、不多一跳、不重复扣费 |
| 领域 handler 已提交后抛错 | unknown 或已确认的部分提交可追踪，不标未执行后重试 |
| all-target 数量超预算 | 明确拒绝或有界完整遍历，不静默少算目标 |
| 两来源修改属性后只移除一源 | 从 base 与剩余贡献重算，不恢复旧快照覆盖另一来源 |
| 重复网络包 / 乱序 / 旧 epoch | 显式拒绝，同一副作用不提交第二次 |
| 迟加入玩家 | 状态同步完整，不重放已提交的历史副作用 |
| 主机迁移 | 未支持时明确中止，不借新 epoch 静默重放 |
| 显示帧率变化 | 逻辑次数由模拟 tick 决定，不能拿桌面 benchmark 宣称 GTFO 帧率 |
| Development 缺失 | 必要玩法仍可运行，诊断支持单独显示不可用 |
